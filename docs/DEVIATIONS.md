| # | SPEC says | What was done | Why |
|---|---|---|---|
| D-01 | Python 3.12 required | Machine had 3.13 and 3.14 only. Installed **Python 3.12.10** side by side with `winget install Python.Python.3.12`; venv built with `py -3.12 -m venv .venv`. | Required by the task. Exact version: 3.12.10 (also at top of `requirements.lock`). All wheels (onnxruntime 1.30.0, ctranslate2 4.8.2, faster-whisper 1.2.1, sounddevice 0.5.6, piper-tts 1.8.0, moonshine-voice 0.1.5) installed from 3.12 wheels; no fallback needed. |
| D-02 | `moonshine-voice` (or `useful-moonshine-onnx`) | Used `moonshine-voice` 0.1.5 (native lib, ships its own downloader). Models downloaded into `models/asr/moonshine` via `get_model_for_language(..., cache_root=...)`. | Verified on PyPI; API read from installed source. |
| D-03 | Silero VAD from `snakers4/silero-vad` | Downloaded `src/silero_vad/data/silero_vad.onnx` from raw.githubusercontent.com. | As specified. Model input is 512 samples + 64 context (v5). |
| D-04 | `OLLAMA_LLM_LIBRARY=cpu`, `CUDA_VISIBLE_DEVICES=-1` | Also set `OLLAMA_VULKAN=0`, `HIP_VISIBLE_DEVICES=-1`, `GGML_VK_VISIBLE_DEVICES=-1`, `OLLAMA_NO_CLOUD=1`. | Ollama 0.35.1 logs `OLLAMA_VULKAN:true` by default; this laptop has an NVIDIA and an AMD GPU, so GPU back-ends are disabled explicitly. Log line `inference compute id=cpu library=cpu` and `/api/ps size_vram=0` confirm. |
| D-05 | Energy: try Energy Meter counters first | **Windows Energy Meter (RAPL package power via PDH)** exists on this machine (`\Energy Meter(RAPL_Package0_PKG)\Power`, mW). Used as the measured energy source, sampled at 2 Hz. It is whole-package power (includes background load); reports also give the idle-subtracted value. A CPU-seconds proxy is logged next to it but always labelled "proxy". | SPEC 9 order of preference. |
| D-06 | Piper release binary if wheel missing | Wheel `piper-tts` 1.8.0 exists for 3.12; used the Python API. Voice sessions are replaced by our own CPU-only ONNX session so thread counts obey the device limit. | Piper's loader builds a default session using all cores. |
| D-07 | Hindi voice `hi_IN-*` | `voices.json` lists `hi_IN-pratham-medium`, `-priyamvada-medium`, `-rohan-medium`; `pratham-medium` downloaded. | Verified listing before choosing. |
| D-08 | Dev-harness only | In this authoring environment (Claude Code), a process placed into the limiter's Job Object is killed when the tool call that owns the job ends. Test fixtures therefore start Ollama with `launch_ollama.ps1 -IfDown` inside each run. The shipped scripts (`run.ps1` etc.) start everything from one console and are not affected. | Harness job-tree cleanup, not a product behaviour. |
| D-09 | 3 repeats per ablation step | Baseline (A0) ran 3 repeats x 60 requests; steps A1-A7 ran **2 repeats** x 60 requests (warm-up discarded) to shorten the real-time benchmark. | Time. Percentiles are still over >=120 turns per step; the repeat counts differ and are stated in `reports/report.md`. |
| D-10 | Cache tau 0.80 / margin 0.05 | tau 0.75 / margin 0.03, chosen on dev paraphrases by `bench/cache_eval.py`; near-verbatim matches (sim >= 0.97) skip the margin test. | Spec says to tune tau on a paraphrase set; spec defaults hit only 27% of paraphrases. Held-out result reported separately. |
| D-11 | Moonshine default threading | `MOONSHINE_ORT_SINGLE_THREAD=1` set in `pv/guard/gpucheck.py`. | With default threads, pinned to 2 CPUs Moonshine took 10+ s per call (measured: finalize 12.9 s vs 0.09 s). |
| D-12 | Hindi + English minimum (S1) | **Tested-partial.** Language detection (Whisper multilingual `base`, run in parallel with speech), Hindi voice selection and Hindi system prompt work end to end; but Whisper-base Hindi transcripts are noisy (e.g. "आप कैसे हैं" -> "अपकेसी है"), so the Hindi cache seldom matches and replies come from the 0.5B/1.5B LLM. Hindi is not claimed as reliable. | SPEC 16 fallback "Hindi voice missing or poor": do not claim it. A larger Whisper model was not downloaded for time. |
| D-13 | Live `Limiter.tighten` sets the Job cap to the target | Cap is set to max(target, current commit + 256 MB) and ratcheted down by the watchdog as the governor frees memory. | Found by test: a Job limit below current usage makes every allocation fail (WinError 1455), i.e. the demo's T key would crash the app. The *declared* limit still changes immediately. |
| D-15 | n/a | Piper's ONNX session leaked ~1.7 MB/sentence (CPU memory arena). Fixed with `enable_cpu_mem_arena=False`. Ladder steps A1-A6 were measured before the fix (their RSS/commit are slightly overstated); A7 was re-run after it (the pre-fix A7 is kept as `bench/out/A7_prefix_leak.json`). | Found by a per-component memory loop. |
| D-14 | Full quantization sweep + quality-by-tier | The quantization sweep (LLM quants, KV cache/flash attention, ASR, TTS, offload) **was run**. | D-16 | (not in spec) Offline knowledge base | Added: Simple English Wikipedia (160k definition-style articles, 82 MB float16 index in `models/kb`) built by `scripts/download_extra.py` + `scripts/build_kb.py` (needs `pyarrow`, setup only). | D-17 | Live default: Moonshine only | Live app re-transcribes each utterance with Whisper `small.en` (`--asr-final`), after mic-gain normalisation, ~+1.7 s per turn; `--asr-final none` restores the fast path. | D-18 | Live default mode | Hands-free `always` mode (VAD + energy gate), half-duplex (mic ignored while speaking, +0.7 s), barge-in opt-in, cache tau 0.85 for live use. | User asked for no SPACE and answers only when spoken to. |
| D-19 | Full tier = `qwen2.5:1.5b` on every profile | Added `quality` (6 cores / 8 GB; T0 `qwen3.5:4b`, then 3B, 1.5B, 0.5B) and `balanced` (4 cores / 5 GB; T0 `qwen2.5:3b`) profiles; `scripts/run.ps1` and `demo.ps1` now default to `quality`.
